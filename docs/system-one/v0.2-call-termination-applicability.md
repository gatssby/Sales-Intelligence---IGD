# System One V0.2 experimental call termination and applicability contract

Status: experimental infrastructure only. No provider execution, inference, database persistence, migration, production routing or scoring formula is authorized by this contract.

## Frozen V0.1 baseline

System One V0.1 remains immutable baseline evidence. This change does not alter or overwrite:

- decision schema `sales-decision-calls-v0.1` and its original ten decision keys;
- chunking contract `pilot-chunking-v0.2`;
- call-level aggregation policy `aggregation-v0.1` implemented by the existing evidence-backed boolean OR, deterministic objection conflict handling and maximum observed buyer intent rules;
- the original private cohort of 30 calls and its manifest/order;
- existing private Laya outputs, raw execution artifacts, summaries, predictions and review queues;
- existing private external-review packets and any GPT/Gemini responses stored under the V0.1 review directory;
- V0.1 human labels and benchmark artifacts.

V0.1 semantics are preserved: `false` means the explicit signal was not observed under the old contract. V0.1 did not separately encode whether the relevant stage was reached.

## V0.2 call completion

The experimental contract version is `system-one-call-decisions-v0.2`.

`call_completion.status` is one of:

- `completed`: evidence shows a natural, coherent closing;
- `explicit_early_end`: one party explicitly states that the conversation must end before its normal flow;
- `abrupt_cutoff`: the transcript ends abruptly without a natural closing or explicit explanation;
- `unknown`: evidence is insufficient to distinguish the states.

`natural_closing_present` is a boolean observation.

`termination_actor` is `lead`, `seller` or `unknown`. `lead` and `seller` require explicit evidence. An abrupt cutoff alone never supports a claim that the internet failed, that a participant disconnected, or that either participant caused the ending.

## V0.2 decision applicability

The ten V0.1 decision keys remain unchanged:

- `pain_identified`
- `impact_explored`
- `price_objection_present`
- `objection_type`
- `objection_handled`
- `social_proof_used`
- `urgency_present`
- `cta_present`
- `next_step_defined`
- `buyer_intent`

Each label adds `applicability`:

- `assessable`: the call provided enough opportunity and context to evaluate the decision;
- `not_reached`: the call ended or changed flow before reaching the situation needed to evaluate the decision;
- `insufficient_evidence`: the decision was potentially evaluable, but the transcript does not support a safe value.

Domain invariants:

1. `applicability != assessable` requires `value = null`.
2. `applicability == assessable` requires the original V0.1 value type.
3. `not_reached` must never be converted to `false`.
4. `insufficient_evidence` must never be converted to `false`.
5. For `objection_type`, `none` is valid only when applicability is `assessable`.
6. `false`, `not_reached` and `insufficient_evidence` are three different domain states.

In V0.2, `false` means absence after the decision was considered assessable.

## Critical CTA distinction

Call A reaches closing and gives the seller a clear opportunity to make a CTA, but no CTA occurs:

```text
cta_present.applicability = assessable
cta_present.value = false
```

Call B ends abruptly during discovery before a closing stage:

```text
cta_present.applicability = not_reached
cta_present.value = null
```

These outcomes are not equivalent and must remain distinguishable in validation, benchmarking and any future scoring layer.

## Scoring semantics, not a formula

No definitive score is introduced in V0.2.

Future policy must preserve these rules:

- `assessable + false` may affect quality scoring;
- `not_reached` does not penalize quality;
- `insufficient_evidence` does not automatically penalize quality;
- assessment coverage is shown separately from quality.

Conceptually:

```text
quality score = performance only across assessable decisions
assessment coverage = assessable decisions / potentially relevant decisions
```

The denominator and relevance policy require separate evidence and are intentionally not implemented here.

## Private human adjudications

Targeted disagreement adjudications live only under ignored `private/system-one/`. They record:

- `label_source = human`;
- `reviewer = leonardo`;
- the applicable `rubric_version` (`v0.1` or `v0.2`);
- `adjudication_type = targeted_disagreement_review`.

The artifact distinguishes confirmed human judgments from hypotheses that still require literal V0.2 review. It contains blind call ordinals rather than production Call IDs and is never tracked.

## Six-call blind pilot

The private V0.2 packet contains exactly the frozen cohort positions `call-01`, `call-07`, `call-10`, `call-15`, `call-25` and `call-28`. The three disagreement cases are paired with the requested high-agreement controls. Source transcripts are copied from the existing blind V0.1 packet, so the original manifest mapping and transcript version remain unchanged without a database read.

Each file contains the complete V0.2 contract and one transcript. It excludes prior model output, confidence, adjudications, review reasons and scores. Transcript content is explicitly untrusted data.

Responses are accepted only as strict JSON containing exactly `call_completion` and the ten typed labels. The local validator requires exactly the six expected response files in each provider directory, rejects extra fields, enforces confidence bounds and requires null for every non-assessable decision.

Run validation only after all twelve response files have been saved:

```bash
npm run system-one:v02:validate
```

## Offline external comparison

After strict validation succeeds, run:

```bash
npm run system-one:v02:compare
```

The deterministic comparator reads only the already-validated GPT and Gemini JSON responses plus the private targeted human adjudications. It does not access transcripts, PostgreSQL, migrations, providers or inference paths. It writes only these ignored private reports:

- `private/system-one/external-review-v02/comparison-gpt-gemini.json`;
- `private/system-one/external-review-v02/comparison-gpt-gemini.md`.

It reports inter-model agreement, not accuracy. Definitive V0.2 human adjudications are compared literally; V0.2 hypotheses remain explicitly excluded from match counts.

## Safety boundary

- private directories use mode `0700`;
- private files use mode `0600`;
- `private/` remains ignored and no private file may be staged;
- the V0.2 module has no provider adapter and no inference path;
- the V0.2 module has no PostgreSQL dependency or write path;
- no migration is added or applied;
- no production schema is modified;
- the external pilot is not executed by this repository change.
